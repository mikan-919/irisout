# 配列の部分更新を変更行へ接続した後の測定

2026-10-16。通常のsignalとJSXを変えず、ADR-0067の所有関係を確認できるmapを変更行へ接続した。1,000行中100行の更新では、配列の参照を複製し、callbackの実行と行の検索・更新を100行分に限定する。全行のキー照合と配置確認を省く。配列の参照複製は配列長に比例するため、処理全体が変更数だけに比例するわけではない。

## 部分更新の交互測定（各200試行）

同じChrome 153.0.8010.12、AMD Ryzen 7 7700 8-Core Processorで、同じ乱数の初期値を使い、毎回1,000行を作ってから一度更新する。3回の事前実行後、実装の順序を交互にして200回測定した。クリックの同期処理とDOM書込みだけを測り、レイアウト・描画を含まない。CPU減速はしない。偶数試行の中央値は中央2値の平均とする。

| 比較                  | 第1実装（ms） | 修正後irisout（ms） | 時間の減少率 |
| --------------------- | ------------: | ------------------: | -----------: |
| 修正前583bff2との比較 |        0.2600 |              0.1900 |        26.9% |
| Solidとの比較         |        0.3500 |              0.2450 |        30.0% |

対応する試行の組を5,000回再抽出した中央値差（修正後−第1実装）の95%区間は、修正前との比較で-0.0950〜-0.0500ms、Solidとの比較で-0.1300〜-0.0875ms。再抽出には初期値42の線形合同法（1664525、1013904223、32ビット）を使う。異なる比較の絶対時間を混ぜない。15試行では修正前との差の区間が0を含んだため、部分更新を200試行で測り直した。

全試行値と生成物のSHA-256は[修正前後](./map-partial-comparison.json)、[Solidとの比較](./solid-map-partial-comparison.json)を参照。

## 公式測定器による部分更新（各5試行、4倍減速）

上流コミットbf894b681fb56433ccb6efb4a3c93e35eda2b20dのPuppeteer測定器と各実装を変更せずに再実行した。両実装の公式キー付き判定も通過した。全体はクリックから描画までの値で、上の同期測定とは別の指標。

| 指標             | irisout（ms） | Solid（ms） |
| ---------------- | ------------: | ----------: |
| JavaScript処理   |           1.7 |         2.4 |
| レイアウト・描画 |          35.2 |        32.1 |
| 全体             |          39.4 |        39.3 |

JavaScript処理の中央値はirisoutが短い。全体の39.4ms対39.3msは各5試行のばらつきに対して小さく、全体での優位は確認できない。各指標の中央値は別々に求めており、足して全体と一致するとは限らない。元の全試行値と起動条件は[map-official.json](./map-official.json)に保存した。以前の全操作の公式比較は[results.md](./results.md)に保持する。

## 費用と適用範囲

直接読み込むスクリプトのgzipサイズは3.80→4.07KiB。HTMLと共通CSSは含まない。測定した修正後スクリプトのSHA-256は`d725efed01bce46eca23236d2e41e8287d32a2bbff83682f1d3e16d2b4531f11`。最終ソースからの再構築でも同じ生成物であることを照合した。

参照先の値を書き換える場合、外部への配列・行の受渡し、任意の関数を呼ぶmap、一般の表示式、共有状態、要求単位SSR、入れ子、ライフサイクルは従来の評価経路を使う。キー変更、別の依存の同時変更、基点が合わない複数mapも通常照合へ戻す。交換時の全行照合は残る。

## 再実行

[README](./README.md)の準備と公式サーバーを使う。583bff2から同じJSXを構築した画面を第1URLに置き、修正後を第2URLに置く。

```sh
JSFB_PROBE_SCENARIOS=partial JSFB_PROBE_SAMPLES=200 JSFB_PROBE_OUTPUT=packages/bench/js-framework/map-partial-comparison.json PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/path/to/chrome bun packages/bench/js-framework/probe.mjs http://localhost:8080/frameworks/keyed/irisout-stage2/dist/index.html http://localhost:8080/frameworks/keyed/irisout/dist/index.html
```

Solidとの比較は第1URLを`http://localhost:8080/frameworks/keyed/solid/index.html`へ変更する。公式の部分更新だけを測る場合は上流のwebdriver-tsディレクトリで次を実行する。

```sh
node dist/benchmarkRunner.js --headless --chromeBinary /path/to/chrome --framework keyed/irisout keyed/solid --count 5 --benchmark 03_
```
