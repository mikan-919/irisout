# ヒートマップのWorker解析計測

## 条件

2026-09-06、NixOS Chromium 152.0.7977.82、3回計測の中央値である。本番生成物を
`/heatmap/`へ配信し、各回は初期解析の完了後に対象文章を入力した。解析時間はWorker内の
Suzumeが返した値、入力から表示までは入力イベントから解析完了表示までのページ内時間である。
表示更新時間はこの二つの差分で、Workerの待機と表示更新を含む。ページ側JavaScriptヒープは
各回の対象入力前後に強制GCして取得し、WorkerのヒープとDOMのnative memoryは含まない。

```sh
IRISOUT_HEATMAP_REPEATS=3 bun run bench:heatmap
```

## 対応範囲と完了基準

この代表アプリの対応範囲を300段落、25,000文字までとする。最大文章で次の基準を満たす
ことを完了条件とし、今回の値はすべて満たした。

- 入力から解析完了表示まで1,000ms以下。
- 入力から表示までの差分100ms以下。
- ページ側JavaScriptヒープ増分32MiB以下。
- キーボードによる段落移動16ms以下。

300段落・24,790文字では、Worker内解析は829.8msだった。一方、キーボード応答は
0.4msであり、解析の待機が画面操作を止めないことを確認した。25,000文字または300段落を
超える文章はこの測定の保証範囲外である。実アプリで超過が必要になった場合は、まず文章を
分割して測定し、表示範囲の限定は全段落表示が問題になった場合だけ検討する。

## 実行経路

`packages/bench/heatmap.playwright.ts`が本番生成、`/heatmap/`の静的配信、Chromiumでの
操作、性能値の取得を一つの経路で行う。Suzumeの解析器とWebAssemblyはWorker内で生成し、
画面側は要求番号を付けて本文を送る。結果の要求番号が最新でなければ捨て、componentの
破棄時にイベント購読を外してWorkerを終了する。

### 限界

- 計測は一つのChromium、Linux環境、代表文章、3回の中央値である。
- ページ側ヒープ値はWorkerとDOMのnative memoryを含まない。
- Workerの処理中に次の入力が来た場合の古い結果破棄は、コンパイラ試験と実ブラウザの
  最終表示確認で検証した。Worker処理自体の中断は行わず、完了した古い結果を採用しない。
