# 公開版アプリの独立操作確認

対象は http://127.0.0.1:4317 。実装ソース、実装担当の記録、過去の報告は読んでいない。課題と既存検査器を読み、HTTPと画面を確認した。既存検査器は8/8合格、追加検査も8/8合格。ブラウザー例外は両検査とも0件。

| 課題                       | 判定 | 観測                                                                                                                                                                     |
| -------------------------- | ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1 一覧・詳細の初期HTML     | 合格 | HTTP 200。JavaScript無効で一覧の3件と各詳細の件名を表示した。                                                                                                            |
| 2 初期API・未知ID          | 合格 | APIにi1/i2/i3、未知IDの詳細は404。既存検査の開始時は3件とも未解決。                                                                                                      |
| 3 検索の競合               | 合格 | HTTP遅延は決済601ms、通知31ms。追加検査で通知200の562ms後に決済200を受信しても通知だけを表示した。                                                                       |
| 4 503と回復                | 合格 | 「検索に失敗しました。もう一度入力してください。」を表示し、完了・成功・更新しましたの表示はない。次の通知検索で失敗表示が消えた。                                       |
| 5 解決と再読み込み         | 合格 | 既存検査でi1を解決。追加検査でi2をSpaceキーで解決し、一覧、一覧の再読み込み、詳細の再読み込み、APIに解決済みを確認した。                                                 |
| 6 ID別メモ                 | 合格 | 既存検査はi1/i2、追加検査はi2/i3で別の値を保存。別IDと一覧への往復、再読み込み後も保持した。                                                                             |
| 7 監視解除                 | 合格 | 同一文書で登録数0→1→0→1→0。各詳細で1回送信すると受信数0→1。追加・解除はそれぞれ2回。                                                                                     |
| 8 要求中の遷移・キーボード | 合格 | Tabで検索と詳細リンクへ移動し、Enterで遷移。決済要求から41msで詳細へ到達し、その時点では未応答。後の200応答でも詳細URL、件名、作業メモを維持し、一覧の検索欄は現れない。 |

既存検査器の探索方法は今回のDOMで成立した。追加検査はラベルと役割を使い、Tabによる選択とEnter・Spaceによる実行を補った。古い応答を排除する観測根拠は、通知の後に決済の200応答が到着しても一覧が通知のままだったことである。実装上の排除手段は未確認。

実行回数は、既存検査器の完走1回、追加検査の完走1回。先行する既存検査器1回は、制限環境内のChromiumが `setsockopt: Operation not permitted (1)` で起動できず、HTTP検査の前に停止した。許可された制限外実行で再実行した。これは環境の制約であり、アプリの失敗は観測していない。

相対import、Honoのloader、`use=`の記述そのもの、依存版、型検査・本番構築は画面とHTTPから確定できないため、この操作確認の判定には含めていない。アプリと本体は変更していない。試験によるサーバー状態としてi1/i2は解決済みになっている。

証拠は `result.json`内の`existing`と`additional`。画面は `search-race.png`、`search-503.png`、`pending-detail.png`。追加検査の再現手順は `additional.mjs`。
