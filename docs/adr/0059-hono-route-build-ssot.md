# ADR-0059: Honoの登録済み経路をVite構築のSSOTにする

## 状態

採用

## 背景

従来はHonoの`createFileRouter()`とViteの`irisoutRoutes()`へ同じディレクトリと接頭辞を指定していた。この構成ではサーバー経路とブラウザー向け構築の設定が重複し、接頭辞の不一致を利用側が防ぐ必要があった。一方、チャンク分割、共有コード抽出、圧縮、資産処理はViteへ委ねる必要がある。

## 決定

`createFileRouter()`が作るページ処理関数へ、ページのファイルパス、依存ファイル、ソース変換を明示情報として付ける。Honoの`app.route()`は処理関数を保持して最終経路を登録するため、`irisoutHono(app)`は`app.routes`からこの明示情報を持つ経路だけを選ぶ。これによりHonoの登録済み経路をSSOTとし、Vite設定にはappだけを渡す。

ブラウザー向け仮想入口はページを動的`import()`で参照する。irisoutは入口と経路表を提供し、チャンク構成と最適化はViteが決定する。`irisoutHono(app)`は通常のViteプラグインを一つ返すため、他のプラグインと同じ配列へ登録できる。

## 結果

- 経路ディレクトリと接頭辞の重複指定を削除できる。
- 通常のHono API経路はブラウザー向けページ表へ混入しない。
- Hono appはサーバー実行時にもVite設定読込時にも評価されるため、app定義で待受を開始してはならない。待受処理は別の起動ファイルに置く。
- 同じページ識別子を別ファイルから複数回mountする構成は、遷移応答の識別子が曖昧になるため拒否する。
