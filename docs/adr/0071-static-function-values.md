# ADR-0071: 関数値を束縛から解決する

決定済み。2026-10-19。const別名、引数経由の呼出し、保存した後始末関数の返却を、既存の関数本体変換へ接続する。ADR-0065の直接呼出しへの制限とADR-0013の生成予約名拒否を改訂する。実行時の関数表や購読機構は追加しない。

関数宣言と関数式を初期値に持つ再代入のない束縛を基点にする。const別名は元の束縛へ辿る。識別子の仮引数は、所有する関数の参照が直接呼出しとconst別名だけで、列挙した全呼出元の対応する実引数が同じ関数本体へ解決する場合だけ受理する。呼出し、実引数の評価、宣言の実行位置は置き換えず、読取り依存・書込み候補・後始末の生成先に共通の解決結果を使う。再代入、異なる本体の実引数、外部へ渡された呼出先、spread、動的に選ばれる関数値は一つへ解決しない。

後始末は従来どおり、元の定義範囲へ表示更新を挿入しない関数を生成する。const別名からこの関数を呼ぶときは、元の別名を評価してから生成先を選ぶ。これにより宣言前参照の例外を残す。識別子で返した更新・後始末も、返却位置を変えずに扱う。初期化と後始末で同じ関数を使っても、通常実行用の本体を後始末用へ上書きしない。後始末の仮引数には更新なしの関数を渡すため、仮引数の同一性や名前を観測する形は拒否する。単純な呼出し・転送以外まで意味を保つ汎用ラッパーは、必要な利用例がないため採らない。

生成名の衝突は作者名の禁止で解決しない。コンパイル中は部品展開が同名宣言を分離した後、作者の`__`・`update_`から始まる束縛と大域参照、および非公開の固定名を一時名で分離し、生成後に衝突する内部束縛だけを移して作者名を戻す。位置編集を使うため、ソース位置の印を含む出力全体の再整形を避ける。関数の`name`・`length`、オブジェクトや入力の省略形のキーを保持する。単に作者の関数名を変える案は`name`の観測結果を変えるため採らない。全生成箇所へ別の命名機構を配る案は、解析と生成の全経路を同時に変更するため採らない。`irisout`の別名importを正規名へ戻す際のトップレベル束縛との衝突と、SSR入力の`signal`・`derived`は、文字列によるAPI識別の境界として残す。

既定引数、クラスフィールド、計算メソッド名は関数本体の更新境界へ含めない。これらから呼ぶ補助関数が状態を参照する場合も診断する。ジェネレーターの中断・再開はこの変更で扱わない。同期補助関数の呼出し開始による更新候補の過剰近似と、共有signal自身の通知は従来の契約を保つ。
