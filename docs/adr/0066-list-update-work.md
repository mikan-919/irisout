# ADR-0066: 一覧の選択、値比較、配置の更新費用

## ステータス

決定済み・実装済み（2026-10-15）。2026-10-16に行の割当とDOM操作を追加で削減した。

## 背景

js-framework-benchmarkの実装で、選択変更も一覧のキー照合を起動し、離れた2行の交換では中間の行まで移動していた。ADR-0015の値比較はDOMへの書き込みを省くが、全行の式評価とMap検索は残る。

ADR-0019とADR-0051のキー付き状態APIはコミット`0efac5e739e0cfdcb0c437ef038621fbedd3af36`で廃止され、現行の`signal`は初期値一つと関数型更新を受け取る。これらのADRに記載された直接通知APIは現行の利用方法ではない。

## 決定

1. 通常の一覧項目で、入れ子構造、局所状態、ライフサイクル、補助関数を持たない場合、前回の値を生成ハンドルの固定プロパティへ保持する。比較は`Object.is`を維持し、未初期化の`undefined`も初回はDOMへ設定する。その他の項目は既存のbinding Mapを使う。共有側の項目状態は、bindingsを初めて参照した時にMapを確保し、項目ごとの同一性と値保存を維持する。
2. 同じ単純な項目では、テンプレート内のマーカー位置を一度だけ求め、複製後は`firstElementChild`と`nextElementSibling`でその位置を辿る。位置を記録したテンプレートから内部のマーカー属性を取り除き、複製する属性数を減らす。位置の記録はテンプレート自身が保持し、入れ子の別factoryや再表示でも再利用する。単一の根要素を直接複製し、行ごとのDocumentFragmentと参照用オブジェクトを作らない。要素参照はハンドルの固定プロパティへ置く。項目ごとのイベントは従来の直接登録を維持し、要素に付けた非公開Symbolから行を参照してWeakMapへの登録・検索を省く。eventの同一性、currentTarget、伝播停止を維持する。
3. 一覧が配列の状態に依存し、本文の外部依存が一つの非共有ルートsignalだけであり、そのsignalの用途が安定した行キーとの`===`または`!==`による属性選択に限られる場合、選択前後のキーを既存Mapへ直接引く。属性の両枝は文字列・数値・真偽値・nullのリテラルに限る。本文の式は行の直接のプロパティ読みに限り、選択状態を読む本文、呼び出し、計算したキー、型変換を伴う比較は対象外とする。選択に無関係な本文は再評価しない。キー式には従来どおり、項目の同一性を表す安定した値を要求する。
4. 配列の更新を含む場合は通常の照合を実行し、選択キーの記録も同期する。初期化も配列側の依存から行い、選択状態が一覧の前で参照されても行を作成する。構造変更と選択変更が同じ同期単位にある場合も照合は一度にまとめる。入れ子、共有状態、一般の式は既存経路を使う。
5. 一覧の配置は一致する先頭・末尾を除外し、残る範囲の最長増加部分列を移動しない要素として採用する。新規要素が続く部分はDocumentFragmentで挿入する。追加の探索は配置が一致しない範囲だけに行う。区間が新規要素だけの場合と両端の交換だけの場合は、実際の兄弟順から判定し、配置用Mapと部分列の配列を作らない。他の配置は従来の照合へ戻す。
6. ライフサイクルを持たない一覧が親の全内容を開始・終了アンカー間に所有する場合、全削除・全置換は`replaceChildren`でまとめる。アンカーの同一性を保つ。静的な兄弟を持つ範囲と、破棄処理を持つ一覧は既存の削除経路を使う。
7. キーの重複検出は各recordへ照合ごとの識別用オブジェクトを記録し、同じオブジェクトの再検出を重複とする。照合途中で例外になっても次回の照合は別オブジェクトを使う。
8. 単純な項目のテキストだけの要素は、既存のText節点のnodeValueを書き換える。空文字でも節点を保持する。外から子の構造が変わった場合はtextContentへ戻して表示を復元する。
9. 単純な行の共有更新関数ではDOM更新取引を重ねて開始しない。呼出し元の一覧更新が取引を所有する。局所状態を持つ親factoryの更新とSSRの構造初期化も外側を一つの取引で囲み、更新前後の通知を保つ。

## 検討した案

- キー付き状態の公開APIを復活させる案は採用しない。現在の`signal`とJSXで適用できる変換を追加する。
- 項目オブジェクトの参照が等しければ更新を省く案は採用しない。オブジェクト内の値が書き換わっている場合を取りこぼす。
- すべての選択式を直接通知へ変える案は採用しない。呼び出し、型変換、他の依存、入れ子構造を含む場合は既存の評価経路を残す。
- 新しいDOM更新用の非同期処理やイベント委譲は導入しない。

## 検証

生成コードを読み込む試験で、初期選択、選択解除、存在しないキー、配列置換、同期した状態変更、空配列後の再作成を確認する。120通りの順列と追加・削除で要素の同一性を確認し、離れた2行の交換が2回の移動になることを固定する。画面の操作は上流のキー付き判定と事後条件でも検証する。処理時間の比較は`packages/bench/js-framework/`に保存する。
