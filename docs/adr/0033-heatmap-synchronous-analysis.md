# ADR-0033: 同期解析の派生値と構造単位の接続

## ステータス

決定済み・実装済み(2026-09-06)

## コンテキスト

ヒートマップの計算は、本文から段落を作り、段落ごとの集計値を作り、その値を表示
する。従来のコンパイラは`derived()`が一つ前のルート状態だけを読む形しか扱わず、
派生値を別の`derived()`から読むとコンパイル時に拒否していた。また、一覧や条件分岐
の中でルート状態を読んだ場合、構造単位のfactoryへ依存が届かなかった。

条件分岐へインライン化した子部品は、変数ゾーンの`signal()`を持つと宣言を置く構文上
の位置がなく、ローカル状態を受理できなかった。

## 決定

- ルートcomponentの状態宣言を解析前に登録し、派生値の依存先を`derivedDeps`へ保存
  する。派生値の依存グラフは循環を検査し、循環があれば`derived dependency cycle`
  のコンパイルエラーにする。
- ルートsignalまたはcollectionから到達できる派生値を依存順に並べ、入力の更新時に
  中間値から最終値まで再計算する。複数入力の同期batchでも同じ順序を一度だけ使う。
  `resolveToSignals()`は派生値を経由して最上位の状態へ依存を戻す。
- 構造unitの本文、動的属性、入れ子unitがルート状態を読む場合、その依存を親markerへ
  持ち上げる。条件分岐のfactoryは必要な本文・属性を更新し、一覧は既存のkeyed
  reconcile経路で行を更新する。別の構造unitが所有するローカル状態への参照は拒否する。
- 条件分岐内の状態付き子部品は、コンパイル時にブランチ全体を0引数arrowのblockへ
  包む。`signal()`、動きゾーン関数、`onMount()`、`effect()`と最終`return`をその
  blockへ置き、通常の構造unit解析へ渡す。生成されたfactoryのhandleがそのローカル
  状態とライフサイクルを所有するため、ブランチ切り替え時に破棄し、再表示時に新しい
  状態を初期化する。
- 初期の代表アプリは`apps/examples/heatmap.jsx`に置く。段落の長さと数値の割合を
  アプリ内の指標定義とし、外部辞書を使わない。色は`class`と`style`、本文への移動は
  `id`と`href`、選択状態と理由は既存の状態・条件分岐で表す。

## 結果

本文→段落→集計→表示値の連鎖を一つの入力更新で再計算できる。複数の入力を書き換える
handlerでも中間の派生値を古いまま使わない。一覧の各行と条件分岐の表示指標はルート
状態の変更に追随する。

状態付き子部品を条件分岐へ置けるため、詳細表示の内部状態は表示中のbranchだけが
保持する。branchを外すと`onMount`のcleanupなどの所有資源を解放し、再表示すると
新しいfactory instanceを作る。

指標の意味はアプリ側に残る。日本語の形態素解析、外部辞書、長文を別スレッドへ移す
処理、古い非同期結果の破棄はこの決定に含めない。

## 検証

- `packages/compiler/test/roadmap-stage3.test.ts`で派生値の連鎖、依存順、複数入力、
  循環診断、一覧・条件分岐内のルート状態、props経由の参照を確認した。
- 同試験で条件分岐内の状態付き子部品を表示、更新、破棄、再表示し、ローカル状態の
  初期化と`onMount` cleanupの順序を確認した。
- `packages/compiler/test/heatmap.test.ts`で本文入力、指標切り替え、選択段落、全体地図
  のリンク、変更後の段落一覧を確認した。
