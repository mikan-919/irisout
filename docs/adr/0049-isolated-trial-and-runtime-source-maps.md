# ADR-0049: 隔離試用と実行時ソースマップの対象

## ステータス

**採用・最初の対象を実装**(2026-09-10)

## 背景

R4では作者以外の人による手動試用を完了条件にしていたが、協力者はいない。そこで、三つの
サブエージェントを初見利用者として使い、リポジトリ実装を参照させず、`/tmp`の独立環境へ
npm公開版`irisout@0.1.0`を導入した。

導入担当は型検査、本番ビルド、開発サーバー、初期HTMLを確認した。アプリ作成担当は入力、
状態、派生値、イベント、条件分岐、キー付きリスト、ファイル分割を含むアプリを構築した。
診断担当は未対応構文、別ファイル部品の誤り、型誤りを診断から修正した。人間による
ブラウザ操作、編集時の再生成、ルート部品の破棄は確認していない。

三者とも、npm公開版向けの開始手順と型検査設定の不足を停止要因として挙げた。未対応の
`try`と`for`は理由を表示したが、原因と異なる行・列を示した。実行時例外については、
生成JavaScriptから元のJSXへ戻すソースマップがないことを採用上の障害として挙げた。

注: ソースマップは、生成JavaScriptの位置と変換前のファイル、行、列を対応付ける情報である。

## 決定

- 人間の協力者がいない場合、公開文書とnpm公開版だけを使う隔離試用をR4の完了判断へ使う。
  人間による試用を実施済みとは扱わず、公開後の確認項目として残す。
- npm公開版の開始手順、型検査設定、初期HTMLの範囲、構造単位の破棄確認を利用者文書へ
  追加する。
- 未対応のハンドラ文は、拒否した文の構文木位置を診断へ渡す。
- 実行時ソースマップを次の実装候補として採用する。最初の対象は、イベント処理、`use=`、
  `onMount`、`effect`に由来する作者記述の文とする。
- 共有実行時処理、DOM探索、リスト照合、条件分岐管理、自動生成した更新関数は最初の
  位置対応対象に含めない。これらには一対一で対応する元構文がない。
- `compileProject()`は、生成位置、連結後の元位置、元モジュールの位置を順に対応付ける。
  Vite連携は、仮想モジュールのJavaScriptと位置対応情報を同じ読込結果として返す。
- 圧縮後の位置対応はVite+へ委ねる。コンパイラは圧縮前の仮想モジュールまでを担当する。

## 最初の実装単位

1. 生成器が出力行と元のファイル、行、列を記録できる内部表現を追加する。
2. ルートのイベント処理一件を対象に、例外位置が元JSXの処理文へ戻る試験を追加する。
3. 別ファイル部品、非同期イベント、`use=`、`onMount`、`effect`へ対象を広げる。
4. 位置対応できない生成処理は、仮想モジュールの位置を維持し、誤った元位置へ割り当てない。
5. 開発時と`build.sourcemap: true`の本番ビルドで位置対応情報が残ることを確認する。

## 採用しない案

- 生成JavaScriptの文字列を元ソースから検索して対応付ける案は採用しない。同じ文が複数ある
  場合と、状態読み取りや更新呼び出しを書き換えた場合に誤った位置を示すためである。
- 全生成行を`render()`位置へ割り当てる案は採用しない。今回修正した未対応構文の診断と同じく、
  原因ではない位置を表示して調査を妨げるためである。
- ソースマップ対応のために汎用AST生成器へ全面移行しない。最初の利用例に必要な位置記録を
  現行の専用生成器へ追加し、内部変更は対象範囲に限定する。

## 結果

R4は、人間の外部試用を未実施と明記した上で、隔離導入、アプリ作成、診断修正から得た
停止要因を修正できた。コンパイラはSource Map v3形式の`map`を生成し、イベント処理、`use=`、
`onMount`、`effect`の処理文を連結元モジュールへ対応付ける。Vite連携は入口ファイルの経路に
問い合わせを付けた内部識別子を使い、コードと地図を同じ読込結果で返す。NUL始まりの仮想
識別子ではVite+の本番ビルドが入力地図を最終地図へ合成しなかったため、この形式は使わない。

共有実行時処理、DOM探索、一覧照合、条件分岐管理、自動生成した更新関数は対応なしの位置を
維持する。全面的な生成コード位置対応を0.1系の保証には含めない。
