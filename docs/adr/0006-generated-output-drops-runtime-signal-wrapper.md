# ADR-0006: 生成コードは signal()/derived() ランタイムラッパーを持たない

## ステータス

決定済み

## コンテキスト

これまでのコンパイラは `signal()`/`derived()` を生成コードの中でも本物の
ランタイム呼び出しとして出力していた(`export const count = signal(0)`、
読み取りは `count()`)。`runtime.js` はビルド時 discovery とブラウザへの
出荷用ランタイムを兼ねる二重の役割を持っていた。

ADR-0005 は、リストアイテムのインスタンスごとの状態については、生成された
factory 関数自身がクロージャ境界を提供するため `signal()` ラッパーが不要だと
既に決定している。この決定を突き詰めると、同じ理屈はトップレベルの
コンポーネント状態にもそのまま当てはまる: コンパイラは自分が生成するコードの
読み書き箇所を完全に静的把握しているので(`declOutputName` で追跡済み)、
signal()/derived() という間接層そのものは、どのスコープであっても出力に
生き残る必然性がない。

ADR-0004 の統治原則(「生成するコードがソースの意味的要求を超えて何かを
実行しない限り、変換・最適化を自由に行ってよい」)に照らすと、この間接層の
除去は方向として常に許される最適化である ― 書かれたものより出力が縮む
(意味的要求を保ったまま間接層を削る)のは問題なく、膨らむ(要求されていない
実行を足す)のだけが禁止される。signal()/derived() 呼び出しをプレーン変数
読み書きに置き換えるのは前者。

## 決定

**著作面(ソース)は変更しない**: 開発者は今まで通り `signal()`/`derived()`
を明示的に書き、`count()` で読み、(将来 M2 で)`count(v)` で書く。ADR-0004
の未決定事項(代入箇所からの静的推論への移行)はここでは解決しない ―
全 JS 代入文法の網羅が必要な話であり、引き続き保留する。

**生成面(出力)を変更する**: コンパイラが自分の生成コードの読み書き箇所を
完全に静的把握している箇所では、signal()/derived() ランタイム呼び出しを
出力に残さない。トップレベルの signal/derived 宣言はプレーン変数として
出力する(`let count = 0;`)。読み取り呼び出し(`count()`)は裸の識別子
(`count`)へ書き換える。`derived` は遅延評価の関数ではなくなるため、依存する
root signal の `update_*` の先頭で、その signal に直接依存する derived を
先に再計算してから、依存マーカーを更新する(この recompute 式は
`analyzeExpr` が出力する call-stripped 版のソースをそのまま使う)。

`runtime.ts` の `signal()`/`derived()` はビルド時専用になる ―
コンパイル中に Node 上で1回実行して初期 HTML を得て discovery を検証する
ためだけに使い、生成モジュールからは一切 import されない。DOM グルー
(`mount`、将来の `hydrate` 等)は逆に生成モジュールへ実際に import される
出荷対象であり、この決定の対象外。

derived-of-derived(derived が別の derived を読む連鎖)は M1 の
スコープ外として明示的に compile error にする。1階層の recompute だけなら
「どの signal が変わったらどの derived を再計算するか」は
`derivedDeps` の直接の逆引きで求まるが、連鎖を許すとトポロジカル順序の
計算が必要になり、今回のスコープを超える。将来 derived-of-derived を
サポートする際は、この決定を判断基準として使うこと ― recompute の追加は
「ソースが要求している依存関係を過不足なく実現する」ものであり続けるべきで、
新しい実行時機構(汎用ディスパッチ、購読リストなど)を持ち込んではならない。

## この決定がこれまでの判断とどう整合するか

- ADR-0005(リストアイテムの factory closure)がアイテムローカル状態に
  ついて既にこれをやっている。この決定はその適用範囲をトップレベル状態にも
  広げるだけで、新しい原則を導入するわけではない。
- 長い設計対話(this session)で確認した「reactive性の実行モデル」とも
  整合する: 実行のトリガーは実DOMイベントのみ(event-driven)、伝播は
  コンパイル時に確定した静的グラフ(`signalToMarkers`)をそのまま辿る
  (pull的、購読リストや実行時依存発見の機構を持たない)。この決定は
  そのモデルの中で「グラフを辿った後、実際に何を実行するか」を
  signal() 呼び出しから直接の変数読み書きへ最適化するだけで、
  実行モデル自体は変えない。

## 未決定事項(後続で詰める)

- derived-of-derived への recompute 順序の一般化(トポロジカルソート)。
- ソース側(著作面)からの `signal()`/`derived()` 除去(ADR-0004 の
  未決定事項、この決定とは独立)。
