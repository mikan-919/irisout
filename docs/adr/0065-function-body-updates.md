# ADR-0065: 関数本体の制御フローを保持する状態反映

障害対応ボードの試用で、内部の関数宣言が拒否された。調査では、末尾に更新文を追加する変換に由来する返却の制限と、非同期補助関数の更新漏れも再現した。ハンドラー、補助関数、内部の関数は共通の解析へ通し、JavaScriptの文と返り値を保持する。通常の関数は書込みを実行したか記録し、`finally`で専用の更新処理を呼ぶ。これにより返却と例外による終了でも状態を反映し、書込み前の返却ではeffectを再実行しない。

同期補助関数は呼出し側でまとめて反映する。呼出し側は追跡呼出し式の評価開始を更新の根拠とし、静的過剰近似を残す。引数の評価が例外で終了した場合にも更新処理を呼びうる。非同期補助関数と内部コールバックは、自分の実行の終了時に反映する。所有範囲とeffectの書込み禁止の検査には、非同期処理も含む全書込み集合を使う。実行時の更新集合と所有範囲の検査集合を分ける。

文の種類ごとに許可を増やす案は、同じ出口の問題を補助関数とコールバックで繰り返すため採らない。書込みのたびに即時反映する案は、同期の複数書込みを一度に反映する契約を変えるため採らない。汎用の実行時購読機構は追加しない。

2026-10-09の次段階では、アクション、`onMount`、`effect`の初期化本体にも同じ終了処理を適用する。返却式を末尾から分離せず、本体と同じ関数内に残す。これにより分岐内の返却と書込み後の途中返却を受理し、返す関数による本体の局所変数の参照を保持する。返却しうるかどうかと依存集合はコンパイル時の情報として保持し、実行時は実際に返った値だけを既存の所有者へ登録する。返却値を先に評価し、作者の`finally`を実行してから状態を反映する。返す関数を作成しただけでは、その内部の書込みを反映しない。

`use`の依存集合は各返却経路の更新関数の読み取りの和集合とする。選ばれなかった経路の依存更新によって、現在の更新関数を呼ぶことがある。`effect`の依存は初期化本体の読み取りに限り、後始末の読み取りを含めない。後始末と`destroy`には表示更新を挿入しない。関数の生成時に`async`を落とす従来の処理は同期の初期化契約を満たさないため、非同期初期化はコンパイル時に拒否する。汎用の非同期初期化の登録機構は追加しない。

ADR-0009の文種と書込み後返却の制限、およびADR-0013の局所関数呼出しと非同期更新の判断を改訂する。残る境界と受入条件は`openspec/specs/handler-statement-bodies/`、`cross-function-handler-writes/`、`element-use-action/`を参照する。

初期化本体と更新関数から直接呼ぶ局所補助関数の読み取りは、呼出しグラフを辿って依存へ合流する。関数の作成と、後始末だけで実行する読み取りは合流しない。後始末から呼ぶ補助関数は、元の定義の字句範囲に更新なしの生成物を置く。同名の関数を後始末へ移す案は、初期化側の同名変数を誤って捕捉するため採らない。通常の生成物と後始末用の生成物を分け、通常の呼出しの状態反映と登録済み監視関数の同一性を保持する。
