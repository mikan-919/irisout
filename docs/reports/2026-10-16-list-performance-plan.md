# 目標

通常のsignalとJSXの意味を保ち、js-framework-benchmarkで確認したVanillaとの差を、不要な処理の削除によって縮め、全9操作でVanilla以下の時間を目指す。

# 対象と基準

D1 対象はブラウザー向けに生成するJavaScriptである。基準は`390f84a`の生成物、調査と全試行値は[Vanillaとの差の再検証](../../packages/bench/js-framework/vanilla-audit.md)を正本とする。コンパイラ本体のネイティブ実行と、生成したJavaScriptの処理時間は別の指標である。

D2 処理量は行数N、変更行数K、新規行数Mで表す。O(K)は変更行数に比例するという意味である。同期時間、描画込みの公式時間、メモリ、転送量を別に評価する。

# 要件（着手順）

R1 **行作成を簡素化する。** 使わない`ItemState`（行ごとの値保存領域）を確保しない。テンプレートの根を一度取得して保持し、同じ親子経路の重複取得を減らす。新しく複製した行の初期テキスト設定では、形状が確定している節点の検査を省く。初期設定と通常更新を区別し、更新時の外部から変更された子構造の復元は維持する。作成・置換・追加とメモリに効く変更から着手する。対象は`codegen.ts`と`runtime/src/index.ts`。

R2 **交換を変更位置へ直接接続する。** 2位置の交換を、一般の配列更新から区別できるようにする。定数1・998という測定固有の値には依存しない。行の検索・値比較・DOM順序確認を全N行に対して行わず、交換対象と挿入位置だけから処理する。隣接、先頭・末尾、同じ位置、範囲外、連続交換を扱う。配列複製の削減はR5に分け、まず照合の全件走査を除く。対象は既存の`list-map.ts`の交換判定、状態書込みの解析、一覧の生成・実行処理。

R3 **追加・削除で保持行を再評価しない。** 末尾追加は新規M行だけの作成・登録・挿入へ接続する。順序を保つ削除は削除キーだけを反映し、残った行の表示値とDOM順序を再検査しない。`filter`によるデータ処理自体のO(N)は残り得る。述語の評価回数・順序・例外を保ち、変更を収集する追加の全行走査を入れない。現在のフィルター判定は行の読取り制限を中心としているため、述語全体の副作用の検査を追加する。対象は`list-map.ts`と一覧の生成・実行処理。

R4 **部分更新を変更フィールドへ接続する。** 行のキーが不変で、ラベルだけが変わる場合は、識別子と選択属性の再比較を行わない。キー保存を静的に証明できる場合は毎回のキー比較も省く。1,000行中100行の更新で必要な100個のテキスト設定へ近づける。まず配列・行の複製を残したまま実施し、参照の意味を変えずに削減できる部分を確定する。

R5 **配列複製と行の確保を分けて削減する。** 古い配列の同一性を観測できない場合は、配列全体の複製を省けるか検証する。古い行をイベント処理内で保持して後から読む場合は、新しい行オブジェクトを残す。行をその場で書き換えるのは、その差を観測する参照が存在しないと確認できる場合だけとする。途中の式評価が例外になった場合に変更済みの値が残らないよう、必要なら変更値を先に評価してから状態を確定する。これを守る追加記録の費用も比較し、改善しなければ採用しない。

R6 **全行削除と残差を調べる。** 全行削除は減速なしの同期比較では差未確定、公式の4倍減速では差がある。0・1,000・10,000行と減速条件を分けて再測定する。境界コメントと兄弟要素を維持し、親を専有する場合だけ一括操作を使う。行ごとの管理情報削減後に、参照の解放、DOM除去、回収処理のどこに差が残るかを調べる。選択は現経路を基準に維持する。

R7 **残ったイベント費用と転送量を判断する。** R1〜R6後にも作成・削除・メモリに差が残る場合、イベント登録の費用を時間測定とは別の比較用実装で切り分ける。既定の配線は維持する。委譲を候補にする場合は、引数を使わないという条件だけで安全とせず、他の処理関数との順序、伝播停止、再入、外部のイベント登録まで検証する。契約変更が必要なら、その必要性と効果を報告してから別の設計判断として扱う。不要になった汎用処理を生成物から除き、圧縮後4.0KiBと作成後2.149MiBからの改善も測る。

# 制約

K1 ベンチマークのJSX、入力、キー、単語表、操作の意味、Vanillaや他フレームワークの実装を維持する。測定専用のID判定、手書きDOM操作、比較先の減速によって差を解消しない。

K2 一般のsignal・共有状態・入れ子・局所状態・ライフサイクルを持つ一覧は従来経路を維持する。最適化を適用できない記述を新たなコンパイルエラーにしない。変更しない行の参照が等しいという理由だけで評価を省略しない。

K3 要素・行・イベントの同一性、キーの重複検出、選択状態、静的な兄弟、開始・終了アンカー、DOM更新通知、破棄順序を維持する。`class`の不存在と空文字属性はDOMから区別できるため、初期属性の省略も観測条件を確認する。

K4 操作の記録を追加する場合は最後に反映した基点を照合する。同じ同期単位の複数操作、配列以外の依存変更、複数一覧、例外、再入で記録が使えない場合は従来の照合へ戻す。行数に比例する履歴を保持し続けない。

K5 配列や行のその場更新を、既存のADR-0067の所有判定だけで許可しない。同ADRが除外した古い行参照の問題を、実行中の処理関数も含めて検査する。

K6 新しい汎用の状態管理機構、非同期の更新管理、公開の一覧操作API、依存パッケージは追加しない。既存の解析と一覧処理を拡張し、最適化が該当しない生成物へ固定費を増やさない。

K7 実装前に該当部分のADRとOpenSpecの提案・受入条件を更新し、検証済みの単位ごとに確定する。この文書は要件と着手順であり、未検証の案を決定済み・実装済みの仕様として扱わない。

# 検収

A1 [R1] 単純な行の生成関数が行状態を使わない場合、未使用のItemState確保は0件となる。複製直後のテキストに対する`nodeType`・`lastChild`の形状確認を省き、通常更新の外部変更復元の試験は通過する。根の取得はテンプレート初期化時に限定する。イベントは既定の2件/行を維持する。

A2 [R2] 2行交換で、行検索とDOMの隣接参照は行数に依存しない回数、表示値比較は0回、DOM移動は最大2回となる。N=100/1,000/10,000の各サイズで有効な位置を使って確かめる。配列複製を残す段階では交換全体をO(1)と報告しない。

A3 [R3] 1,000行に1,000行追加した際の保持行1,000行の表示値比較は0回、DOM順序の全件走査は0回となる。新規行のキー照合は残す。1行削除でも保持行999行の表示値比較と順序の全件走査は0回となる。データ配列の述語評価は元の回数・順序を保つ。

A4 [R4,R5] ラベルだけを100行更新した際、テキスト設定は100回、識別子・選択属性の比較は0回となる。キーが変わる式では従来の重複検出・再利用を維持する。複製を省いた場合は、古い参照、例外、連続書込み、別名、複数一覧の回帰試験を追加し、どの確保が何件減ったかを示す。

A5 [K2,K3,K4,K5] 生成物を実行する試験でDOM同一性と値、イベント、範囲所有、例外後の次の操作を検証する。対象外へ戻る試験を含める。各段階で`bun run check`と全試験、一覧の変更では公式のキー付き判定と8操作を通す。最終段階では構築、梱包、文書、サーバー、保存、Motion、Playgroundも確認する。

A6 [R1,R2,R3,R4,R5,R6,R7] 各段階では影響する操作を修正前後とVanillaで交互に各100回測る。時間測定中に処理回数の計装や他の検査を並行しない。生成物のSHA-256を保存し、前段階と異なる生成物の値を混ぜない。効果が測定変動から区別できなければ試行を追加し、効果未確認として記録する。

A7 [目標] 最終評価は全9操作の同期比較を独立した3組で各100回、公式CPUを各10回（選択20回）、メモリ各3回、転送量を実施する。各組の実装順を交互にし、中央値・絶対差・比率・95%区間を示す。目標は同期・公式の両方で各操作の中央値がVanilla以下となることであり、区間に0が含まれるだけで同等達成とは判定しない。複数操作・複数組の比較による不確かさも明記する。

A8 [R7,目標] 作成後メモリと圧縮後転送量は現在の2.149MiB・4.0KiBを基準にし、Vanillaの1.882MiB・2.5KiBを目指す。計算量、同期処理、描画、メモリ、転送量のいずれかが改善しても、他項目の悪化を隠さない。採否は全指標と実装の複雑さを記録して判断する。

A9 [目標] 未達項目は残差と必要な処理を報告する。「除去可能」「現仕様では必要」「費用の寄与が未確認」を区別し、実装の完了を全項目で最速を達成したことへ読み替えない。

# 未確定事項

Q1 R2・R3で必要となる操作の記録形式は、既存の基点照合を再利用する案と、書込みから一覧へ直接渡す案を比較して決める。汎用の操作履歴は作らない。

Q2 R5で配列の複製だけを省く条件と、行の確保まで省く条件の証明範囲は別に定める。例外前に確保・評価した結果を一時保存する費用が、削除する費用を上回る場合は採用しない。

Q3 R7のイベント委譲は現行の直接配線契約を変更する案であり、この計画の速度目標を達成する前提には置かない。現契約を維持して到達できない差があれば、その時点で数値とともに報告する。
