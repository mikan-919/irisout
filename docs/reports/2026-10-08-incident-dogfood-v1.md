# 障害対応ボードの利用者試験 v1

確認日: 2026-10-08。対象: ローカル梱包物irisout 0.3.7、Vite+ 0.3.0、TypeScript 5.9.3、Hono 4.13.13。npm公開物の導入試験ではない。

## 問いと条件

公開文書だけから、要求単位SSR、共有文書部品、Hono API、ページ遷移、検索応答の競合、キー付き一覧、ID別localStorage、監視解除を組み合わせられるか。課題は`fixtures/incident-dogfood/brief.md`に置いた。

実装役Aは別ディレクトリで作業し、本体の実装、既存アプリ、他の試行を読まない。型検査と構築の検査・修正は最大5回。操作役は実装ソースを読まず、HTTPと画面を検査する。操作役へのPlaywright入口指定を親が誤り、存在する入口へ訂正した。この訂正は製品修正に数えない。

## 結果

| 検査                               | API接続前              | 接続後 |
| ---------------------------------- | ---------------------- | ------ |
| JavaScriptなしの初期HTMLと詳細件名 | 合格                   | 合格   |
| API、検索遅延、未知ID404           | API404で停止           | 合格   |
| 古い検索応答を選ばない             | 不合格                 | 合格   |
| HTTP503の表示と次の検索で回復      | 不合格                 | 合格   |
| 解決状態を一覧と再読み込みへ反映   | 不合格                 | 合格   |
| ID別メモの分離と保持               | 合格                   | 合格   |
| 同じ文書内の監視登録と解除         | 合格                   | 合格   |
| 検索中の詳細遷移とキーボード操作   | 遅い応答の条件は未確認 | 合格   |

Aは5回目に型検査と本番構築を通過した。2回目はpython3不在で編集が適用されず、同じ失敗を再検査した。これも回数に含める。API接続後は独立操作役の8項目が通過した。監視数は0→1→0→1→0→1、イベント1回で受信数0→1。追加観測では検索開始から56msで詳細へ移り、602ms後に届いた応答で詳細が変わらず、文書も同じだった。

## 役立った説明

実装役Aの原文:

> 「古い要求の取り消しや競合結果の選択はアプリ側で管理する。」要求番号が最新と等しい時だけ成功・失敗の状態を反映。

> 「`onMount`はDOMの接続後に一度実行される。返した関数は破棄時に一度実行される。」localStorage読込みをここへ置いた。

## 止まった箇所と対応

- 内部の関数宣言: 「文書に『handler内の関数宣言は禁止』の明記はない」。`const`アロー関数へ変更し、監視解除の例を文書へ追加。[課題記録](../issues-drafts/incident-dogfood-listener-declaration.md)
- Hono構成: 「Hono構成の本番構築に必要な入口設定が文書から分からない」「文書にはAPIの中継方法がない」。構築入口とAPIの接続例を追加。[課題記録](../issues-drafts/incident-dogfood-hono-wiring.md)
- 契約の不一致: 記述境界が要求単位SSRを否定し、API文書がJSX返却を否定していた。現行の専用文書と説明を合わせた。[課題記録](../issues-drafts/incident-dogfood-authoring-contract.md)

今回は文書を修正した。本体の不具合は確定していない。Aの回避策はViteの知識から推測したため、Aの成功だけでは文書修正の効果を判定しない。次は修正文書と同じ課題・5回の予算を、新しい実装役Bへ渡す。

## 検査の限界

操作検査はChromium 154.0.8037.57、1280×900。公開版の隔離導入、本番サーバーからの生成資産配信、保存失敗、外部認証、端末間同期、速度の比較は対象外。Bun導入のEROFS、待受とブラウザー起動のEPERMは実行権限の拡張で解消した。

`vlmkit` 0.23.0の`check integrity`は、付属ブラウザーが`error while loading shared libraries: libglib-2.0.so.0: cannot open shared object file`で起動できず未実施である。8項目の操作合格は、表示崩れ検査の合格を意味しない。
