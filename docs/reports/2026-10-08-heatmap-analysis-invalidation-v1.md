# 情報量ヒートマップ: 古い解析結果を無効化する (2026-10-08)

## 問い

本文を上限超過まで編集したとき、情報量ヒートマップが現在の本文に属さない解析値を表示しないか。

## 結果

| 確認                         | 変更前                                                     | 変更後                                                    |
| ---------------------------- | ---------------------------------------------------------- | --------------------------------------------------------- |
| 25,000文字を超える本文へ置換 | 上限超過を表示し、古い合計語数と同じ段落番号のスコアを残す | 上限超過を表示し、合計語数を0、段落スコアを解析待ちへ戻す |
| 上限超過前のWorker応答       | 要求番号が進まず、遅れて届いた結果を採用する場合がある     | 要求番号を進め、古い応答を破棄する                        |
| 実ブラウザー                 | 未確認                                                     | NixOS Chromium 154.0.8037.57で確認                        |

実ブラウザー計測はNixOS Chromium 154.0.8037.57で3回行った。最大入力300段落・24,790文字の中央値はWorker解析860.4ms、入力から表示881.8ms、表示更新14.4ms、ページ側ヒープ増分490,588Bだった。操作確認ではキーボード移動0.8ms、IME確定後の解析、上限超過時の`単語数 0`と`解析語数: 0`を確認し、既存の完了基準を満たした。

## 発見 — エージェントの報告

> “stale token analysis is displayed against over-limit edited text.”

初見のエージェントは、Worker解析を受けた後に25,000文字超の本文へ置換する操作で、statusだけが上限超過になり、既存の`analysisResults`と`tokenCount`が残ると特定した。段落スコアは番号で以前の解析結果を参照していた。

## 対応

有効な入力の再解析を始めるとき、および上限超過を検出したときに、解析結果を消す。上限超過も最新要求として番号を進め、先に送った応答を破棄する。画面側は合計語数を0、段落解析を空へ戻す。

`packages/compiler/test/heatmap.test.ts`に、上限超過で新しいWorker要求を送らないこと、合計語数と段落値を消すこと、古い応答を無視することを加えた。`packages/bench/heatmap.playwright.ts`は300段落を解析中に上限超過の本文へ連続して置換する実Chromium操作を追加した。

## 変更後の確認と次の計測

> “Existing heatmap unit test passed: `bunx vp test packages/compiler/test/heatmap.test.ts` (5/5).”

変更後、既存のヒートマップ試験5件、追加した上限超過確認、実Chromiumの計測を通した。独立したエージェントによる再実行は一時localhost bindの`EADDRINUSE`でブラウザー起動前に止まり、再確認には使えなかった。主エージェントのChromium実行は成功した。

Workerの解析自体は中断せず、結果だけを破棄する。入力が続く場合の待ち行列が編集を妨げるかは今回計っていない。連続編集の応答時間を測ってから、中断または要求の集約を加えるか決める。
