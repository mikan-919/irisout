# 初期化関数の制御フロー

2026-10-19にconst別名・識別子引数を経由する呼出しと、保存した更新・後始末関数の返却へ対応した。この文書の残る境界は当時の記録を保持する。現行ソースの条件は[関数値の境界](./2026-10-19-javascript-boundaries.md)を参照する。

`cd7a654`を基準に、`use`・`onMount`・`effect`の分岐と途中返却を実装した。末尾の返却を本体から切り離す方式を廃止し、本体と返却を同じ関数内で変換する。返却式を評価し、作者の`finally`を実行してから、実行した書込みを表示へ反映する。返した関数は本体の局所変数を参照でき、実行した分岐の更新・後始末だけを登録する。破棄と初期化失敗時の回収は既存の所有者の処理を使う。

初期化や更新関数が直接呼ぶ局所補助関数の読み取りを依存へ合流した。関数の作成や、後始末だけで実行する読み取りは初期化の依存へ含めない。後始末から呼ぶ補助関数には表示更新を挿入しない生成物を使い、元の定義範囲を保持する。後始末内へ同名関数を移す試作は、初期化側の同名変数を誤って参照するため採用しなかった。

変更前には次を再現した。

- 分岐内の返却は3種類の初期化で拒否された。[返却の証拠](./evidence/2026-10-08-lifecycle-returns-before.jsonl)
- 初期化や更新関数から直接呼ぶ局所補助関数の読み取りが依存から漏れた。[読み取りの証拠](./evidence/2026-10-08-lifecycle-local-read-before.json)
- 項目の後始末から補助関数を呼ぶと、内部の即時・非同期処理が生存中の親の表示を更新した。[後始末の証拠](./evidence/2026-10-08-lifecycle-cleanup-before.json)
- 非同期初期化が受理され、`async`が失われた生成物の読み込みに失敗した。初期化は同期処理とし、現在は位置付き診断で拒否する。[非同期初期化の証拠](./evidence/2026-10-09-lifecycle-async-before.json)

## 検証

独立した受入試験と[Chromium検査器](../../fixtures/lifecycle-control-flow/README.md)を保存した。生成コードを実行し、mount/hydrate、局所変数の参照、返却式とfinallyの順序、書込み前の返却、元の例外の再送出、逆順で一度だけの後始末、初期化失敗時の回収、keyによる項目の所有、effectの依存と後始末の分離を確認する。

初期化の40試験と補助関数の37試験を追加し、[全48ファイル・453試験](./evidence/2026-10-09-lifecycle-tests.log)が成功した。`bun run check:fix`による書式・型検査、`bun run build`、公開物の構築を含む`bun run pack:smoke`、`bun run site:check`も成功した。梱包物の別ディレクトリーへの導入先は`/tmp/irisout-consumer-G4SAa3`。Chromium 154.0.8037.57の[8項目の最終結果](./evidence/2026-10-09-lifecycle-browser.json)はすべて成功し、ページ例外はなかった。梱包物の構築と並行した最初の全試験では構築を含む2試験が失敗し、梱包終了後の再実行で全試験が成功した。

局所補助関数の[変更後の読み取り](./evidence/2026-10-09-lifecycle-local-read-after.json)と[変更後の後始末](./evidence/2026-10-09-lifecycle-cleanup-after.json)も再実行した。即時処理・Promise・非同期補助関数のどの後始末経路でも、生存中の親の表示は更新されなかった。

最初のブラウザー検査では、検査器がアクションとonMountをまとめて逆順に破棄すると誤認し、4項目が失敗した。既存実装と仕様の所有者ごとの逆順へ期待値を修正した。[最初の結果](./evidence/2026-10-09-lifecycle-browser-first.json)を保存した。既存のソース位置試験で見つけた後始末の1行のずれは、ASTへ戻す関数本体の位置マーカーを保持して修正した。

## 残る境界

初期化は同期処理に限る。返却式はvoid、直接の引数なし関数、`use`の更新・後始末オブジェクト、およびそれらを選ぶ条件式に限る。関数を変数へ保存して返す形、別名や引数を経由する呼出し、動きゾーンの補助関数をコールバックへ渡す形、後始末から関数値を渡して実行する形は次の段階で扱う。登録済み監視を解除する`removeEventListener`の参照は保持する。

再代入した関数を後始末から呼ぶ形も位置付き診断で拒否する。関数変数の生成物は元の宣言が実行される位置を保持し、宣言を実行せずに返却した場合の宣言前参照の例外を保持する。関数の名前・引数数・型・同一性を読むだけの処理は、関数値を渡して実行する処理とは区別する。

共有signalの設定関数自身が通知する動作は維持する。抑止するのはコンパイラが後始末へ挿入する専用の表示更新であり、共有状態の通知機構は変更していない。

返却分岐の更新依存と補助関数の書込み候補は静的な和集合であり、実行した分岐の厳密な依存集合ではない。入れ子の関数の位置マーカー終了後、外側のfinallyがソース位置へ戻らない問題は[変更前後で再現](./evidence/2026-10-09-lifecycle-source-map-review.jsonl)し、今回の対象外として記録する。この不具合は2026-10-18に、位置マーカーの階層と元の終端位置を保持する修正で解消した。回帰試験は`packages/compiler/test/source-map.test.ts`にある。画像比較と性能比較は実施していない。npmへの公開とGitの送信は行っていない。
