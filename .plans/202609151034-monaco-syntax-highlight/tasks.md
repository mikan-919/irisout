# C1

C1-T1 既存の Monaco Editor 0.56.0 の遅延読込みと作業スレッド設定を使い、Playground のモデルを JavaScript/JSX の言語定義で構成する。キーワード、文字列、コメント、JSX タグ、JSX 属性を色分けできる状態にし、既存のテーマ、読取り専用状態、アクセシビリティ属性を保つ。補完、意味解析、診断、TypeScript 固有機能は追加しない。 [R1,K1,K2,K3]
done: 初期値を持つ `[data-playground-monaco]` が読み込まれたとき、同じ Monaco モデル上で JavaScript/JSX の代表的な構文要素を言語トークナイザーが識別でき、既存の表示設定と作業スレッド設定が残っている。

C1-T2 C1-T1 の言語設定を実ブラウザー試験で検証する。初期ソースにキーワード、文字列、コメント、JSX タグ、JSX 属性を含め、Monaco 読込み後の表示値と各構文要素の色分けを確認する。 [R1,A1]
done: Chromium で `[data-playground-monaco]` の初期表示を開いた後、代表する各構文要素が通常のテキストと同一表示にならず、構文に応じたトークン表示になっている。

# C2

C2-T1 C1-T2 のモデルを維持したまま、初期値、Monaco 上の編集、例の切替え、共有値の複製、既存 `textarea` からの入力の各経路でソース値を同期する。Monaco の編集値を既存の `textarea` と入力イベントへ反映し、`textarea` を参照する保存・書き出し・実行の値経路を保つ。値の置換後もモデルを再作成せず、言語定義と構文ハイライトを維持する。 [R2,R3,K3,A2,A3] <- C1-T2
done: 実ブラウザー試験で各経路の表示ソースと `[data-playground-source]` の値が一致し、Monaco 編集時の入力同期、例の切替え、共有値の複製、読取り専用状態の遷移が既存どおり動作し、置換後も構文ハイライトが残っている。

C2-T2 C2-T1 の値経路を使って、保存、書き出し、実行を継続できることと、Monaco 本体または言語機能の遅延読込み失敗時に `textarea` へ退避できることを確認する。退避時に初期値・複製値・利用者入力を失わず、投稿ソースの変換、実行管理画面、別配信元の境界を変更しない。 [R3,R4,R5,K3] <- C2-T1
done: Monaco 資産を読み込めないブラウザー試験で `textarea` が表示されて入力・保存・書き出しを継続でき、正常経路では同じソースで実行まで完了し、実行管理画面との既存の境界検査が変わっていない。

C2-T3 C2-T2 の実装と試験を完了条件で検証する。 [K1,K2,K3,A4] <- C2-T2
done: `bun run typecheck:web` と `bun run test:web:playground` が成功し、JavaScript/JSX 単一入力、既存テーマ、読取り専用状態、アクセシビリティ属性、Monaco 読込み失敗時の退避に関する受入条件を満たしている。
