# Goal
ファイル構造から共通の経路定義を生成し、`irisout/hono`のHonoサブルーターと`irisout/ssr`に接続するクライアント遷移用経路表へ変換して、ブラウザー内の画面切り替えまで提供する。

# Terms
D1 経路定義: URLの照合規則、経路引数、対応するページの識別情報を持つ、両方の変換先で共有する定義。
D2 サブルーター: 利用側のHonoアプリケーションへ指定した接頭辞で組み込める経路群。
D3 クライアント経路表: ブラウザーでURLに対応するページと経路引数を判定し、画面切り替えに使う生成物。

# Req
R1 指定したディレクトリのファイル構造から経路定義を生成し、利用者がサーバー用とクライアント用の経路を二重に記述せずに済むこと。
R2 静的な経路と動的な経路引数を表現し、両方の変換先で同じURLが同じページと引数へ解決されること。静的経路を動的経路より優先し、同順位の経路が衝突する場合は対象ファイルを示して生成を失敗させること。
R3 `irisout/hono`から共通の経路定義に対応するサブルーターを提供し、既存のHonoアプリケーションに組み込めること。接頭辞を付けた場合もクライアント経路表との対応を保つこと。
R4 ページ経路を`irisout/ssr`の描画へ接続できること。各ページのHTML、初期状態、ブラウザー用生成物の対応を保ち、要求間で入力や状態を共有しないこと。
R5 クライアント経路表にサーバー専用の処理や依存を含めないこと。ブラウザーでの照合にファイルシステムやHonoを要求しないこと。
R6 ファイルの追加・削除・名前変更が次の生成結果の両方へ反映され、削除前の経路が残らないこと。
R7 未一致のURLは未一致として扱い、別のページへ誤って解決しないこと。
R8 ディレクトリ単位の`page.jsx`規約を採用する。`routes/page.jsx`は`/`、`routes/users/page.jsx`は`/users`、`routes/users/[id]/page.jsx`は`/users/:id`へ対応し、`page.jsx`以外のファイルをページとして登録しないこと。
R9 管理対象ページへの通常の同一生成元リンク操作と履歴の戻る・進むで、文書全体を再読み込みせずにURLに対応する画面へ切り替えること。外部リンク、ダウンロード、別タブ操作、同一文書内の断片移動はブラウザーの標準動作を保つこと。
R10 画面を置き換える際は旧画面のイベント処理や副作用を破棄し、連続した遷移で先の応答が後の遷移先を上書きしないこと。遷移先の取得または描画に失敗した場合は、そのURLへの通常の文書遷移でサーバーの応答を表示できること。
R11 ページごとにサーバー側のデータ取得処理を対応付け、直接アクセス時のSSRと画面切り替えで同じ処理を使用すること。取得処理には経路引数、検索引数、要求情報を渡せ、非同期の取得結果をページの描画入力にできること。取得処理のないページも扱えること。
R12 取得結果のうちページへ渡すJSON値だけをブラウザーへ搬送すること。取得処理の実装と依存、要求オブジェクト、接続情報は搬送しないこと。初回のハイドレーションのために取得処理を再実行しないこと。
R13 データ取得側で未検出や転送を返せること。直接アクセスでは対応するHTTP応答を返し、画面切り替えでも同じ結果を扱うこと。例外時は正常ページ用の状態やサーバー内部の情報を返さないこと。
R14 ルート以外の末尾の斜線は除いて照合し、経路引数は一度だけ復号すること。不正な符号化と、復号後に経路区切りとなる引数は未一致とすること。検索引数と断片は経路照合に含めず、検索引数の変更による遷移ではデータを再取得すること。

# Constraints
K1 公開パッケージは`irisout`一つを維持し、`irisout/hono`を副入口として追加する。既存の`irisout/ssr`、`irisout/vite`の利用方法を維持する。
K2 既存SSRの`render(input) -> { html, state }`とJSON状態の制約を維持する。ハイドレーション（サーバー生成済みのDOMにイベント処理と状態を接続する処理）は対応する生成物と状態を使う。
K3 SSR部品の相対モジュール読み込みなど、既存コンパイラの未対応記法をこの計画で暗黙に解禁しない。経路の生成と部品のコンパイルは区別する。
K4 この文書は要件案であり、受入条件の正本は`openspec/specs/`とする。実装に進む際は対応する仕様変更へ反映する。
K5 HTML文書の組み立ては既存の利用方法と同じく利用側が担当する。データ取得処理の配置、公開関数名、遷移用の応答形式は実装分割時に決める。サーバー専用の取得処理をSSR部品のコンパイル対象へ混ぜない。

# Non-goals
N1 既存アプリケーションのHonoへの移行、認証機構、配備環境の追加。
N2 入れ子のレイアウト、任意の経路制約、先読み、遷移中の状態保持。必要性が確認された場合は範囲を再検討する。
N3 API処理のファイルからの自動登録。利用側のHonoアプリケーションに手書きしたAPIを併設することは妨げない。
N4 複数階層をまとめて受ける経路、任意の階層を省略できる経路、フォーム送信やデータ更新の自動処理。ページ遷移に必要なデータ搬送はR11〜R13の対象であり、N3の対象外にはしない。

# Done
A1 [R1,R2,R3,R5] 静的経路と動的経路を含む同じファイル集合から両方の生成物を得て、同じURLに対するページ選択と引数の一致を確認できる。
A2 [R2] 動的経路と静的経路が両方一致するURLでは静的経路が選ばれ、重複する動的経路は両方のファイルを示す診断になる。
A3 [R3,R4] 生成したサブルーターを接頭辞付きで組み込み、ページへの直接アクセスで得たHTMLと状態を対応するブラウザー生成物へ渡せる。
A4 [R5] ブラウザー向け生成物の依存にHono、ファイルシステム処理、サーバー専用処理が含まれないことを確認できる。
A5 [R6,R7] ファイルの追加・削除・名前変更後に再生成し、両方の変換先で新しい経路が一致し、削除した経路が未一致になる。
A6 [R4,K1,K2] 既存の単一部品SSR利用が維持され、異なる入力による同時要求のHTMLと状態が混ざらない。
A7 [R8,R9] `users/[id]/page.jsx`に対応するページへリンクから遷移し、戻る・進むでもURLと表示が一致する。文書全体の再読み込みは発生せず、直接アクセス時と同じ経路引数が渡る。
A8 [R9,R10] 外部リンクと別タブ操作の標準動作を維持し、連続遷移の応答順を逆転させても最後の遷移先を表示する。旧画面の処理が残らず、取得失敗時は対象URLへの文書遷移へ移れる。
A9 [R11,R12] `/users/123`への直接アクセスとリンク遷移で同じ取得処理が引数`123`を受け取り、その結果の名前を表示する。初回のハイドレーションでは再取得せず、ブラウザー向け生成物に取得処理とその依存を含めない。
A10 [R11,R13] 取得処理のないページ、非同期取得、未検出、転送、例外を直接アクセスと画面切り替えの両方で確認し、失敗応答に正常ページ用の状態や内部情報が含まれない。
A11 [R2,R14] 末尾の斜線、符号化された引数、不正な符号化、検索引数を含むURLで両方の照合結果が一致し、検索引数だけを変えた遷移でも取得処理へ新しい値が渡る。
