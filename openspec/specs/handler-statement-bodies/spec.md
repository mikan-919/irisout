# handler-statement-bodies

## Purpose

ハンドラ本体(inline arrow のブロック本体、および識別子参照の解決先
function 宣言の本体)のJavaScriptの文、返り値、例外を保持する。
第1引数によるイベントオブジェクトの受け渡しと、signal書込みの代入への変換、
実行した関数の終了時の状態反映を扱う。

## Requirements

### Requirement: ハンドラのブロック本体の受理
コンパイラは、ハンドラ本体(inline arrow のブロック本体、および識別子参照の
解決先 function 宣言の本体)として、式文、`const`/`let`/`var`、ブロック、
条件分岐、ループ、ラベル、`switch`、`try`/`catch`/`finally`、`throw`、
関数宣言、クラス宣言、値のある/ない`return`を受理しなければならない(SHALL)。
文の種類を列挙して許可する検査を置かず、通常の制御フローを保持する。
状態アクセスは束縛先によって解決し、内部の関数は実行境界を分けて解析する。

#### Scenario: ADR-0008 の決定例がコンパイルできる
- **WHEN** authored コンポーネントが `render()` の後ろに
  `function handleCountUp() { state(state() + 1) }` を宣言し、JSX から
  `onClick={handleCountUp}` で参照する
- **THEN** コンパイラは compile error を出さずに完了し、生成コードを
  実行するとクリックで `state` の表示が更新される

#### Scenario: 4文種すべてを含む本体がコンパイルできる
- **WHEN** ハンドラ本体が「裸の `return` を持つ `IfStatement`(ガード)→
  `const` ローカル宣言 → `IfStatement` → 追跡 signal への書き込み式文」の
  順で4文種すべてを含む(`apps/demos/todomvc.jsx` の `handleInputKeyDown` 相当)
- **THEN** コンパイラは compile error を出さずに完了する

#### Scenario: inline arrow のブロック本体も同じ解析を通る
- **WHEN** authored コンポーネントが
  `onClick={() => { const n = count() + 1; count(n) }}` のようにブロック本体の
  inline arrow ハンドラを持つ
- **THEN** コンパイラは compile error を出さずに完了し、生成コードを実行すると
  クリックで `count` の表示が更新される

### Requirement: イベント引数の authored 名での受け渡し
コンパイラは、ハンドラの第1仮引数(単純な識別子)を受理し、authored の
引数名をそのまま生成ラッパーの第1仮引数へ昇格しなければならない(SHALL)。
本体内でのその引数の参照(メンバーアクセス・代入を含む)は書き換えずに
出力する。分割代入の仮引数・第2引数以降は受理しない。

#### Scenario: イベントオブジェクトを参照するハンドラ
- **WHEN** ハンドラが `function h(e) { if (e.key !== 'Enter') return ... }` の
  ように第1引数 `e` を宣言して本体で参照する
- **THEN** コンパイラは compile error を出さずに完了し、生成コードを実行して
  対象要素にイベントを dispatch すると、リスナは実際のイベントオブジェクトを
  `e` として受け取る

#### Scenario: 引数名が追跡 signal 名と衝突しても引数が勝つ
- **WHEN** top-level に `const value = signal(0)` があり、ハンドラが
  `function h(value) { ... }` と同名の引数を宣言して本体で `value` を参照する
- **THEN** 本体内の `value` は引数として解決され、signal の読み書きとしては
  扱われない(出力名への書き換え・`update_*` 生成が起きない)

#### Scenario: 分割代入の仮引数の拒否
- **WHEN** ハンドラが `({ target }) => { ... }` のように分割代入の仮引数を持つ
- **THEN** コンパイラは `compile:` で始まり `(scope limit)` を末尾に含む
  エラーを投げる

### Requirement: 文中の signal 書き込みの検出と代入への変換
コンパイラは、ブロック本体中の追跡 signal への引数1個の呼び出し
(`todos(next)`)を書き込みとして検出し、生成コードでは代入
(`todos = next`)へ書き換えなければならない(SHALL)。書き込み先は静的に収集するが、
反映はその関数の実行時に行う。ローカル変数宣言・引数によるシャドーイングは
書き込み検出の対象外に落とす。代入式を括弧で区切り、書込みの返り値と
周囲の演算子の優先順位を保持しなければならない(SHALL)。

#### Scenario: 文中の書き込みが代入へ変換される
- **WHEN** ハンドラ本体の文中に `todos([...todos(), item])` のような追跡
  signal への書き込みがある
- **THEN** 生成コードには `todos = [...todos, item]` に相当する代入が含まれ、
  `todos(...)` の呼び出し形は残らない

#### Scenario: 条件分岐内の書き込みでも update が生成される
- **WHEN** 書き込みが `if (cond) { count(1) }` のように分岐の内側にのみある
- **THEN** 生成ラッパーの終了処理に `update_count()` の呼び出しが含まれ、実行時に
  分岐が成立した場合は表示が更新される

#### Scenario: ローカル宣言が signal と取り違えられない
- **WHEN** ハンドラ本体が `const count = 99` のように追跡 signal と同名の
  ローカルを宣言して参照する
- **THEN** そのローカルへの参照は書き換えられず、`update_count()` の生成
  対象にもならない

### Requirement: 関数の終了経路と返り値の保持
コンパイラは、通常の終了、値を返す/返さない返却、例外による終了のいずれでも、実行した書込みを関数の終了時に反映しなければならない(SHALL)。書込み前に返却する経路では、その関数の書込みを理由とするDOM更新やeffect再実行を行ってはならない(SHALL NOT)。元の返り値と例外を保持し、作者が書いたfinallyを実行してから状態を反映する。書込み候補の集合は静的に求めるため、同じ実行で一部だけ書いた場合にも候補全体の更新を行いうる。同期補助関数の呼出しは静的過剰近似を維持し、追跡呼出し式の評価開始を更新の根拠とする。引数の評価が例外で終了した場合にも更新処理を呼びうる。

#### Scenario: 書込み後に値を返す
- **WHEN** ハンドラーまたは補助関数がsignalへ書き込んだ後に値を返す
- **THEN** 表示を更新し、元の返り値を呼出し側へ渡す

#### Scenario: 書込み後に例外を投げる
- **WHEN** 関数がsignalへ書き込んだ後に例外を投げる
- **THEN** 書込みを表示へ反映し、元の例外を呼出し側へ伝える

#### Scenario: 作者のfinallyも状態を書き込む
- **WHEN** try内の返却または例外に続き、finallyがsignalへ書き込む
- **THEN** 作者のfinallyを実行した後の状態を表示へ反映する

#### Scenario: 書込み前に返却する
- **WHEN** 関数がガード条件で返却し、signal書込みも追跡補助関数呼出しも実行しない
- **THEN** その関数を理由とするeffectの再実行を起こさない

### Requirement: 内部関数の実行境界と返り値
コンパイラは、内部の関数宣言、関数式、アロー関数、オブジェクトメソッド、クラスメソッドを実行境界ごとに解析しなければならない(SHALL)。関数を作成しただけで、その内部の書込みを理由とする更新を起こしてはならない(SHALL NOT)。式本体をブロックへ変換するときは元の式の返り値を保持する。

#### Scenario: Promiseコールバックの返り値を保持する
- **WHEN** Promiseのコールバックが式本体またはブロック本体でsignalへ書き込み、値を返す
- **THEN** コールバックの終了後に表示を更新し、次のPromise処理へ元の返り値を渡す

#### Scenario: 内部のクラスメソッドが状態を更新する
- **WHEN** 関数内のクラスメソッドがsignalへ書き込む
- **THEN** クラスの作成時には書込みを反映せず、メソッドの実行時に反映する

### Requirement: 引数と中断可能な関数の残存境界
イベント引数は第1引数の単純な識別子に限る。ジェネレーターの関数本体を黙って通常関数として出力してはならない(SHALL NOT)。対応外の場合はscope limit診断で拒否する。既定引数、クラスフィールドの初期値、計算されたメソッド名など、解析する関数本体の外の状態API参照も同じ分類の診断で拒否する。関数の中断位置と本体の外の実行境界は、通常の関数出口への反映とは分けて実装する。
