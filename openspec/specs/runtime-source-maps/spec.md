# runtime-source-maps Specification

## Purpose
生成JavaScriptで発生した実行時例外を、利用者が記述したJSXのファイル、行、列から調査できるようにする。

## Requirements

### Requirement: 作者記述の実行位置を元モジュールへ対応付ける

コンパイラは、イベント処理、`use=`、`onMount`、`effect`に由来する生成JavaScriptの位置を、
作者が記述した`.jsx`または`.js`のファイル、行、列へ対応付けるソースマップを返さなければ
ならない(SHALL)。

#### Scenario: ルートイベント処理の例外

- **WHEN** ルート部品のイベント処理に由来する生成コードで例外が発生する
- **THEN** ソースマップは例外位置を元の処理文があるファイル、行、列へ対応付ける

#### Scenario: 別ファイル部品の例外

- **WHEN** 相対モジュールから合成した子部品の処理に由来する生成コードで例外が発生する
- **THEN** ソースマップは入口ではなく子部品の元ファイル、行、列へ対応付ける

#### Scenario: 非同期処理の例外

- **WHEN** `await`より後ろを含む非同期イベント処理に由来する生成コードで例外が発生する
- **THEN** ソースマップは例外位置を対応する元の処理文へ対応付ける

#### Scenario: ライフサイクルとアクションの例外

- **WHEN** `use=`、`onMount`、`effect`に由来する生成コードで例外が発生する
- **THEN** ソースマップは例外位置を対応する元の処理文へ対応付ける

### Requirement: 元構文のない生成処理へ誤った位置を割り当てない

コンパイラは、共有実行時処理、DOM探索、リスト照合、条件分岐管理、自動生成更新関数のうち、
対応する作者記述を特定できない位置を別の元構文へ対応付けてはならない(SHALL NOT)。

#### Scenario: 共有実行時処理の例外

- **WHEN** 作者記述と一対一に対応しない共有実行時処理の位置をソースマップで照会する
- **THEN** その位置は無関係な`render()`、イベント処理、または部品宣言へ対応付けられない

### Requirement: Vite連携がソースマップを引き継ぐ

Vite連携は、仮想モジュールのJavaScriptとコンパイラが生成したソースマップを同じ読込結果で
返し、開発時とソースマップを有効にした本番ビルドへ引き継がなければならない(SHALL)。

#### Scenario: 開発時の仮想モジュール

- **WHEN** Vite+が`virtual:irisout-entry`を読み込む
- **THEN** 読込結果は生成JavaScriptと元モジュールを含むソースマップを持つ

#### Scenario: 本番ビルドの外部ソースマップ

- **WHEN** 利用アプリが`build.sourcemap: true`で本番ビルドを行う
- **THEN** 出力されたソースマップから対象の生成位置を元モジュールへ戻せる

### Requirement: 既存コンパイル結果との互換性を保つ

ソースマップ追加後も、コンパイラは既存の生成JavaScript、初期HTML、依存一覧を維持しなければ
ならない(SHALL)。ソースマップ生成のためにブラウザ用JavaScriptへ位置記録処理を追加しては
ならない(SHALL NOT)。

#### Scenario: ソースマップを使わない利用者

- **WHEN** 利用者が既存どおり`code`と`initialHtml`だけを使う
- **THEN** 既存のコンパイル、初期化、更新、破棄の動作は変わらない
