## ADDED Requirements

### Requirement: 所有配列の構造操作を変更行へ限定する
所有関係と反映基点を確認できる固定位置の交換・末尾追加・純粋な削除では、保持行の値比較とDOM順序の全件走査を省く（SHALL）。一般の述語、基点不一致、他の依存変更、例外後は従来照合を維持する（SHALL）。新規キーの重複検出と、配列複製・述語評価の意味を維持する（SHALL）。

#### Scenario: 交換と保持行
- **WHEN** 所有配列の二位置の交換、末尾追加、純粋な削除を反映する
- **THEN** 交換は行検索と隣接参照を行数に依存しない回数とし、追加・削除は保持行を再評価しない。操作の基点が不一致なら全体を照合する

### Requirement: 平坦な行の初期処理を限定する
状態を使用しない平坦な行は、未使用の項目状態を確保しない（SHALL NOT）。項目状態が参照された場合は項目専用の状態と値保存領域の同一性を維持する（SHALL）。新規複製の初期テキスト設定と、外部の子構造変更から復元する通常更新を区別してよい（MAY）。

#### Scenario: 状態を使わない行と参照時の状態
- **WHEN** 平坦な行を作成し、その後同じ行の状態を複数回参照する
- **THEN** 作成時は項目状態を確保せず、参照後は同じlistId・itemIdを持つ同じ状態と値保存領域を返す

#### Scenario: 初期設定と通常更新
- **WHEN** 新規複製のテキストを初期化し、その後外部で子構造を変えて値を更新する
- **THEN** 初期化は既知の節点へ直接書き、通常更新は宣言したテキストへ復元する

#### Scenario: 共通経路と空の選択属性
- **WHEN** 平坦な通常要素の行が同じ親子経路の表示・イベント参照と、空文字にもなる選択用classを持つ
- **THEN** 先に取得した要素から後続参照を辿り、空属性をテンプレートへ移してよい。空文字でも属性の存在を保ち、カスタム要素とisを含むテンプレートは属性移動を行わない

### Requirement: 部分更新の変更フィールドと非共有配列を使う
コンパイラが行の展開と上書きフィールドを確認できる場合、変更しない直接参照の本文・選択属性・キー検証を省いてよい（MAY）。配列の複製を省くには、設定後の別名使用、ループ、任意の呼出しによる途中観測がないことを追加検証する（SHALL）。行の古い参照、例外、複数一覧、生成関数の再入による評価順を維持する（SHALL）。

#### Scenario: ラベルの部分更新
- **WHEN** 非共有配列の100行をラベルだけ変更する
- **THEN** 配列複製を維持し、テキストを100個更新し、識別子・選択属性・キーの比較を省く。新しい行オブジェクトは確保する

#### Scenario: 古い参照と例外
- **WHEN** イベントが更新前の行を保持する、mapの評価が例外になる、交換の設定前に関数を呼ぶ、または追加の生成関数が配列を更新する
- **THEN** 古い行の値と例外前の状態を保ち、交換の途中観測を許す場合は複製し、追加の既存部分は生成関数を呼ぶ前の値を使う
