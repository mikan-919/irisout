## Context

共有は編集時点のスナップショットであり、既存IDを更新しない。公開ページのSSRは運営側部品が担い、保存されたJSXは文字列として表示する。要求本文の上限、ID、再送、削除の初期契約は計画に記載する。

## Goals / Non-Goals

**Goals:**

- アカウントなしで保存、直接URL閲覧、複製保存、管理鍵削除を成立させる。
- 応答消失、通信断、削除後再送、保存先停止で入力や削除状態を壊さない。
- 管理鍵と投稿ソースをログ、OGP、読取りデータから分離する。

**Non-Goals:**

- 公開一覧、認証付き非公開、既存IDの上書き、編集履歴。
- 保存したJSXのサーバーコンパイル、診断、生成HTML、画像の保存。

## Decisions

- IDはサーバーで128ビット以上の乱数から生成し、requestIdと入力・管理鍵の一致で再送を識別する。
- 管理鍵はブラウザで生成し、サーバーはハッシュだけを保持する。読取りURLと管理操作を分離する。
- 削除は閲覧不能化と表示値の消去を一トランザクションで行い、再送識別に必要な最小記録だけを残す。
- 保存値はHTML・Markdownとして解釈せず、表示時の文脈でエスケープする。
- APIは公式OriginからのJSON POSTと管理鍵付きDELETEだけを受け付ける。

## Risks / Trade-offs

- [管理鍵紛失で自己削除できない] → 保存前と完了画面で紛失時の扱いを表示し、別操作で書き出せるようにする。
- [応答消失で重複保存される] → requestIdと一意制約をトランザクションで処理する。
- [削除済み共有が復元で戻る] → 削除記録と復元手順を運用changeで検証する。

## Migration Plan

内部接続として実装し、保存・再送・削除・再起動の検査が通るまで公開入口を有効にしない。形式を変更する場合はschemaVersionと移行手順を追加する。
