## Context

`compile()`は文字列から初期HTMLと生成コードを作るが、現在の公開パッケージはNode依存を含むコンパイラとmodule linkerを同じ経路に持つ。Playgroundは単一ソースだけを扱い、投稿ソースをサーバーへ渡さない。

## Goals / Non-Goals

**Goals:**

- ブラウザで実行可能な単一ソース入口を作る。
- Node組込み、ファイル読込み、外部module解決をブラウザ用生成物から排除する。
- 既存の診断と対応範囲をそのまま再利用する。

**Non-Goals:**

- ブラウザ内の複数ファイル解決、npm依存、module linkerの移植。
- 投稿コードをサーバーでコンパイルする経路。

## Decisions

- 入力は文字列と明示的なコンパイラ版だけにし、ファイルパスを受け取らない。
- コンパイラ本体の静的解析部分とNode依存のmodule linkerを別bundle境界にする。
- 対応外のimportや外部資源は未対応として診断する。無視して実行しない。
- 生成コードは既存runtime境界を使い、ブラウザ用入口固有の汎用runtimeを追加しない。

## Risks / Trade-offs

- [コンパイラbundleが大きい] → 依存一覧と起動時間を測定し、文書物から遅延分離する。
- [Node依存が間接的に残る] → 本番生成物の依存検査とブラウザ実行で確認する。
- [単一入口と既存入口の診断がずれる] → 同じ公式例を両入口へ渡し、結果と診断を比較する。

## Migration Plan

新しい副入口を追加し、既存入口は維持する。梱包検査とブラウザ試験が通った後にPlaygroundのWorkerから読み込む。
