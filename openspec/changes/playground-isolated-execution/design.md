## Context

ブラウザ用コンパイラ入口は別changeで追加する。Workerは実行単位を分けるが、権限分離や通信禁止を自動で保証しないため、別配信元とiframeの権限指定を組み合わせる。

## Goals / Non-Goals

**Goals:**

- 投稿ソースと公式サイトのCookie、管理鍵、保存APIを分離する。
- 無限ループ、例外、時間超過、古い応答から操作を復旧できるようにする。
- 生成HTMLと生成JavaScriptを結果iframe内へ限定する。

**Non-Goals:**

- 投稿コードのサーバー実行。
- 完全なCPU・メモリ隔離の保証。実行環境が提供する上限の確認を別途行う。

## Decisions

- 親画面から実行管理iframeへ渡すのはソース、版、実行番号だけにする。
- Workerは実行ごとに生成し、終了経路を共通化して破棄する。
- 結果iframeは`allow-scripts`だけを初期値とし、同一生成元、フォーム、上位遷移、ポップアップ、ダウンロードを許可しない。
- メッセージは固定形式として検証し、親画面で受信値をHTMLとして挿入しない。
- 外部配信元、CSP、Worker応答のヘッダーを実機で検査してから本番設定を決める。

## Risks / Trade-offs

- [iframeだけでは無限ループを止められない] → Workerを停止し、結果iframeを破棄して実行番号を無効にする。
- [sandboxの設定漏れで権限が広がる] → 許可する属性を仕様に列挙し、通信と遷移を試験する。
- [メッセージの遅延で古い結果が反映される] → 実行番号を全応答へ付け、現在値と一致しない応答を破棄する。

## Migration Plan

保存・共有を有効にする前に隔離環境を試作する。試験が失敗した場合は共有公開を止め、編集機能をローカルの検証範囲へ残す。
