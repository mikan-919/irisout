## Context

決定済み ADR-0008(ゾーン API)は、ハンドラを `render()` より後ろの
function 宣言(ブロック本体)で書くと決めたが、現行コンパイラは
`src/compiler/render.ts` でハンドラのブロック本体(`isBlockStatement()`)と
引数(`params.length > 0`)を明示的な scope limit として拒否している。
`src/compiler/analyze.ts` の `analyzeHandlerExpr` は単一式のみを前提に、
`count(count() + 1)` のような「追跡対象識別子への引数1個の呼び出し」を
書き込みとして検出し `writeDeclIds` に集める。識別子解決は
`idPath.scope.getBinding(...)` ベースの `resolveDeclId`。`src/codegen.ts` の
ハンドララッパーは既に `(...__args) =>` と可変長引数を受けているが、渡された
引数は現状捨てられている ― イベントオブジェクトは配線上ラッパーまで届いて
おり、欠落は解析側(引数の受け入れと本体内参照解決)のみにある。

`examples/todomvc.jsx` の `UNRESOLVED(09)`(イベント引数の型付け、
`e.target.value` への素朴なアクセス)がこの ADR が答えるべき具体的な入力の
1つ。

**この変更は設計スパイクであり、成果物は ADR ドラフト(レビュー待ち)である。
`src/**`・`test/**` への実装コミットは行わない。**

## Goals / Non-Goals

**Goals:**
- ハンドラのブロック本体・イベント引数・分岐内書き込み検出・
  `analyzeHandlerExpr` の拡張形・ADR-0008 との接続の5点について、
  推奨案・根拠・代案を1本の ADR ドラフトにまとめる。
- 検証可能な技術判断(ローカル変数の scope 解決、シャドーイング、早期
  return 時の書き込み検出)を使い捨てスクラッチ実験で検証し、ADR の根拠に
  引用する。

**Non-Goals:**
- 実装そのもの(ADR 承認後の別の変更に委ねる)。
- ref の設計(ADR-0008 の未決定事項、M5 の後と既に決定済み ― 本 ADR には
  含めない)。
- 既存 ADR(0001〜0008)の改訂(矛盾が見つかった場合は ADR に記録しつつ
  ドラフトのまま提示し、改訂は別途ユーザー判断を仰ぐ)。

## Decisions

### 1. 5つの設計質問を1本の ADR にまとめる(分けて決めない)

ADR-0008 の実装(文レベルのハンドラ解析)とイベント引数のサポートは、
どちらも `analyze.ts` の同じ解析層を触る。別々の ADR で決めると解析層を
二度設計するリスクがあるため、1本のドラフトにまとめる。

### 2. イベント引数はハンドラの仮引数名をラッパーの仮引数へ昇格する案を軸に検討

`src/codegen.ts` のハンドララッパーは既に `(...__args) =>` を出力している。
仮引数名(`e` など)をそのままラッパーの仮引数名として出力する案
(`(e) => { ... }`)を軸に、第1引数のみ許すか分割代入も初回スコープに
含めるかを ADR 内で検討する。

### 3. ブロック本体で最初に許す文種は最小集合から始める

`ExpressionStatement` / `VariableDeclaration`(const/let ローカル)/
`IfStatement` / `ReturnStatement` を出発点の推奨案とし、ループ・try は
ADR-0007 の「安全に拒否」原則に従い scope limit として明示拒否を維持する
方向で検討する。

### 4. 検証はリポジトリ外のスクラッチで行う

`@babel/parser` + `@babel/traverse` を直接使い、`resolveDeclId` の
`getBinding()` がブロック内のローカル宣言・シャドーイング・早期 return 内
書き込みをどう解決するかを確認する。結果はコードとしてはコミットせず、
ADR 内に文章と最小コード片として引用する(`docs/architecture.md` の
「設計変更の進め方」1〜2段階 ― ADR を書く前の調査はスパイクとして扱う)。

## Risks / Trade-offs

- [スクラッチ実験で `getBinding()` がローカル変数を誤って追跡対象へ解決
  すると分かった場合、現行 `resolveDeclId` の設計前提自体が崩れる] →
  これは ADR の範囲を超える発見として明記し、ADR 本体では「未決定事項」
  として切り出す。既存 ADR の改訂はこの変更の権限外。
- [検討の結果、ADR-0008(識別子参照+巻き上げ function 宣言)の決定と
  矛盾する結論にしかならない] → 既存 ADR は改訂せず、ドラフトの
  「未決定事項」として記録し、ユーザー判断を仰ぐ。
- [許可する文種の集合が TodoMVC に必要な最小を超えて膨らむ] →
  ADR-0007 の「安全に拒否」原則に従い、最小集合から始めて拡張は別途
  決定する運用にする。
